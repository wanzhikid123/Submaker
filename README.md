# Submaker Studio

Windows 字幕工作台：本地 Whisper 识别 → 多接口并行 LLM 翻译 → 一次全片审校与自动修正 → GPU 烧录字幕，生成译名视频。

支持多视频队列、双 GPU 调度、可选源语言与目标语言、逐接口并发/RPM/effort、任务恢复及 RAM 音频缓冲。当前版本 **v0.5.6**，已在 16 线程 CPU、双 Tesla V100 上验证。识别和视频处理在本机完成，字幕文本及原文件名会发送至用户配置的 LLM 接口。

## 启动

先按下方“安装 / 构建”完成本机安装。之后可双击桌面 **Submaker Studio**、项目中的 `Start-Submaker.cmd`，或在项目目录运行：

```powershell
.\Start-Submaker.cmd
```

构建后的 `dist/SubmakerStudio/SubmakerStudio.exe` 是本机安装版启动器，使用项目目录中的隔离 Python 环境；请一起保留 `.venv`、`submaker`、`models` 和 `assets`，不能只复制 EXE 到其他电脑。源码仓库不包含 Python 环境、模型权重、视频或本地交付包。

1. 打开“API 与高级设置 → 翻译接口池”，填写接口名称、地址、模型、Key、并发与RPM，测试后保存。可以添加OpenAI、OpenRouter、Google AI或自定义兼容接口，分别填写模型与Key并启用。支持完整 `.../chat/completions` 或基础地址，模型 ID 按所选服务实际支持的名称填写。
2. 选择识别语言、翻译语言、GPU 和线程。默认日语 → 简体中文、GPU0+1、CPU16线程。常用语言可直接选，源语言也可输入 Whisper 语言代码，目标语言可自定义。
3. 添加视频/文件夹或拖入视频，点击“开始队列”。配置按任务快照保存；更改语言/API后，选任务点“使用当前设置重试”。
4. 新视频默认放在原视频目录，可在设置中更改输出目录。成品仅包含字幕烧录后的 `译名.mkv`，不生成独立SRT。重名自动另存为 `.v002` 等，原文件不覆盖。

API 尚未填写时可先完成本地识别，文字恢复点会保留；填好接口后重试可复用。应用通过 **Windows 凭据管理器**保存 Key，配置文件保存接口 URL、模型 ID、参数和凭据引用；这些本地配置均不应提交到仓库。

## 运行方式

- 最多3个在途视频；多视频分卡，单视频可跨卡识别不同窗口；每卡一个常驻模型。首个稳定完整句立即提交，后续最多缓冲1秒、按小批次翻译，不等待整片或整个窗口。恢复后的已识别文字按最多20段合批，已存译文直接复用。
- 不同视频的翻译队列轮流调度，共享API名额按等待顺序分配。等待翻译时持续更新已译条数、执行/排队批次数和等待时间；审校、标题等实际API请求也显示当前等待秒数。
- GPU0/GPU1的用途、显存、解码和编码利用率集中在顶部GPU WORKERS；GPU利用率使用圆环显示，≤70%为绿色、>70%为黄色、>90%为红色，无数据时显示灰色。每1秒后台采样，面板每250毫秒更新，任务阶段事件立即更新；独立刷新不重建任务表格。
- 收到HTTP 429时在详细信息显示接口名称、退避与实际/配置并发，分别保存各接口的已知限流次数。同端点/凭据引用统一冷却、实际并发减半，稳定后逐步恢复，设置值不改写。单接口遵循Retry-After或缺省10/20/40秒退避；翻译池把未完成批次交给其他尚未失败的接口。同一批次不重复选择刚失败的接口，全部接口不可用后保留恢复点并显示顶部橙色提示。额度不足、认证/配置失败停用对应接口；超时、5xx和无效JSON也可切换。旧版历史次数无法补回，429不能单凭状态码断定是并发过高。
- 提供高质量、均衡、快速预设，默认高质量；调整识别搜索和视频编码，所有预设仍进行全片审校。
- 暖白色界面；字幕预览默认关闭，在“API 与高级设置 → 资源与输出”开启。字幕字体从系统字体下拉列表选择。
- “删除选中任务”支持Ctrl/Shift多选，“清空全部任务”停止并清理全部任务；只删除任务记录和运行缓存，保留源视频与已完成的视频。
- “视频编码”页可选H.264/H.265、GPU速度档位、CQ质量和体积策略。加载视频后后台读取媒体信息，队列按当前编码设置显示预计大小与范围；完成后同时显示成品实际大小，预计值按该任务保存的编码设置计算。已有任务使用保存的快照，点击“使用当前设置重试”可更新。
- 音频通过 FFmpeg 管道和有界 RAM 数组传递，不创建临时 WAV/FLAC。缓存预算默认8GiB，系统内存低于约4GiB时暂停预取；预算不包含模型与程序自身内存。Windows 仍可能分页。
- 翻译池最多8个接口，每个可启用、停用或移除；主接口可以停用。各接口独立控制模型、effort、并发与RPM，空闲接口轮流领取批次；同端点和凭据引用共享较低的并发/RPM上限。等待RPM的首发批次留在队列，不占用HTTP执行线程，不阻碍其他接口的任务。
- 新任务的全片上下文、审校、自动修正和文件名翻译固定共用“全片审校 / 文件名”页的接口、模型、effort与凭据，并共享其并发/RPM；默认继承主翻译接口。自动修正不再交给翻译池，完成后直接导出。文件名无需单独配置，旧版独立标题配置不再使用。已有任务保留保存的修正方式，重试不会自动迁移此策略或清除已完成进度。
- 每接口默认30 RPM，0表示不限制；按服务配额设置，均匀发送并限制滚动60秒预算，重试、审校及标题请求也计入。界面显示预算与等待原因。额度为本工作台进程的本地预算，其他应用或账号共享用量无法得知；RPM不能消除TPM、日额度或服务端拥塞导致的限流。
- effort 默认 `default`，不发送该参数；可以输入服务支持的档位并测试，已通过测试的档位保存在下拉列表。接口不支持时明确报错，不静默忽略。
- 全片翻译完成后进行一次审校，结合全片摘要和邻接上下文覆盖全部字幕；自动修正发现的问题，然后直接导出，不再复审，也不需要人工质量判断。
- 阶段进度直接显示审校已完成批次，例如“全片审校 12/17”；等待处理、暂停或完成时显示实际任务状态，错误原因保留在详细信息与顶部提示中。
- 单接口回复的 JSON、审校字段或字幕编号有误时，用该接口的模型和参数提示纠正，最多3次格式尝试；多接口翻译池收到无效JSON时可先切换尚未尝试的接口。仍失败会保留恢复点并暂停。全片摘要、各批审校和局部修订分别保存，重试时复用已完成步骤。
- API 默认每接口并发2、超时300秒。单接口最多3次尝试；翻译池有限切换，每个原始翻译批次含拆批、纠正、切换最多10次实际请求。认证/模型/参数错误熔断，手工重试解除。暂停会中止本地等待，但不能撤销服务端已产生的用量。
- 每接口并发可设置1至16，总HTTP执行线程最多128，按任务需求扩展。增加接口后复用仍在启用池中的已完成译文；各批次保存实际接口来源，统一经历一次全片审校。
- 每个任务显示累计“总 tokens / requests”，包含翻译、上下文、审校、修正、文件名翻译及重试。requests在HTTP发起时累计，包含429、超时和无效回复，不把排队或发送前取消计为请求，也不因收到usage重复计数。tokens只累计接口返回的usage；缺失用量不估算，旧版无法补回的请求次数与用量分别以≥标记。统计随任务历史保留。
- 暂停/退出保留少量文字恢复点；重启后“开始队列”可继续暂停任务。成功验证成品后立即删除任务运行缓存，保留视频、模型、配置和简要任务历史。烧录所需的临时ASS文件在成功、失败、取消时均清理；已完成任务不保留独立字幕预览文本。
- 改 GPU、线程、模型目录、RAM 或在途任务上限后，请暂停并重启工作台，再用当前设置重试。一个工作台进程使用一份全局资源配置。

## 接口异常与 RPM 提示

| 情况 | 显示位置与内容 | 自动处理 |
|---|---|---|
| HTTP 429 | 详细信息显示接口名、倒计时、实际/配置并发、已知限流次数；翻译池全部失败后顶部提示 | 共享冷却、暂时降低实际并发；翻译池尝试其他尚未失败的接口 |
| 达到本地 RPM 预算 | 任务详细信息显示接口名、已用/上限和等待秒数；不触发顶部橙色告警 | 等待可发送时机，其他接口可继续处理 |
| 超时、5xx、无效JSON | 详细信息显示对应接口及原因；翻译池全部失败后顶部提示 | 有限重试或切换尚未失败的翻译接口 |
| 认证失败、参数错误、额度不足 | 详细信息记录异常；无可用接口时顶部提示 | 暂停对应接口；无可用接口时保留恢复点等待处理 |
| 内容策略拦截、模型拒绝、异常终止 | 顶部橙色提示和任务详细信息，显示接口名及公开原因码，例如 PROHIBITED_CONTENT | 保留恢复点并等待处理，不将 HTTP 200 视为生成成功，不自动重试或切换接口处理被拒绝的批次 |
| 多次无效回复、重试耗尽或本地处理错误 | 顶部提示和任务详细信息，阶段显示“等待处理” | 保留已有进度；不继续显示旧的运行阶段 |

单个翻译接口发生可切换故障时，详细信息显示“已切换其他接口”并保留原因和429次数；其他接口成功不会删除这条记录。全部翻译接口不可用后，顶部提示列出各接口的失败原因。审校/修正使用固定单接口，失败不会转入翻译池；内容策略拦截或模型明确拒绝直接保留进度并提示，不转发被拒绝的批次。当前是界面提示，没有弹窗或声音通知。RPM是本进程的主动节流预算，HTTP 429则是服务端拒绝请求，二者分别显示。

任务启用的翻译接口固定显示在详细信息中，即使待命或尚未发出首个请求也会保留。每个接口分别显示请求/等待、实际/配置并发、RPM与累计429次数；独立审校配置单独标注“全片审校”。切换配置后，旧配置的429次数仍以“历史配置”保留，不将历史错误误报为当前限流。列表按任务保存的快照生成；启用新接口后，已有任务需要暂停并使用当前设置重试才能加载。

## 视频与质量

默认 MKV + V100 NVDEC 解码、H.265 NVENC编码，P6/slower、CQ26与紧凑体积策略，参考源视频码率设置目标与峰值限制。可选H.264；GPU速度从very fast/P2到very slow/P7，均调用NVENC。质量优先模式允许码率自由变化，也可指定视频码率。估算包含保留的音轨，实际大小受画面复杂度影响，不保证固定压缩比例。

自动分配所选GPU，每卡一个导出任务，可双卡并行；可固定GPU0/1。不受支持的源格式使用CPU解码，GPU编码失败不会自动转CPU。10-bit需H.265；当前GPU路径不能完整保留静态HDR元数据时提前停止，可显式选择CPU兼容编码。Dolby Vision / 动态HDR当前会阻止输出，避免静默丢失元数据。

按现有CPU线程预算并行解码和字幕滤镜，每个导出任务两部分各最多4线程；16线程、双卡时各分配4线程。保留所选NVDEC/NVENC、预设、CQ、双遍和码率参数。双V100上三段60秒样本较旧版提速约1.5–2倍，解码后的逐帧画面与样本编码大小一致；实际整片速度取决于素材和同期负载。详见[性能实测摘要](docs/performance.md)。CPU兼容编码路径保持原线程策略。

视频逐帧在显存/RAM中解码、渲染字幕和编码，不写解码帧、原始音频或中间视频缓存。FFmpeg直接写入最终成品的`.partial.mkv`路径，校验成功后在同一目录改名，不复制或重写整部视频；成品本身需要写盘。仅有小型临时ASS和可恢复的文字/配置/统计写盘，ASS在退出烧录阶段时清理，任务成功后清理恢复点。Windows的内存分页不由应用控制。

显式CUDA上传对照中，60秒720p样本当前路径6.95–7.23秒、显式上传7.28秒，未测得额外提速；保留现有质量参数与路径。NVENC是专用编码硬件，CUDA滤镜适合额外的视频处理，不能直接替代NVENC加速已有编码。详见[性能实测摘要](docs/performance.md)与[NVIDIA说明](https://docs.nvidia.com/video-technologies/video-codec-sdk/13.1/nvenc-application-note/index.html)。

保留兼容音轨、附件、其他视频轨和章节。新视频只呈现烧录字幕，不内封原有软字幕，也不生成独立SRT，避免重复加载。原视频不改动。成品检查时长、显示尺寸、音轨、无软字幕轨、附件、章节及HDR标志。

Whisper、LLM审校均不能保证自动达到人工翻译质量。当前验证覆盖实际GPU、长片时间戳范围、并发、恢复、接口合约及媒体输出；真实模型翻译质量、人工词句和同步参考集需要实际API和人工样本验收。详见 [验证记录](docs/validation.md)。

## 安装 / 构建

目标是 Windows x64 + NVIDIA GPU。先安装可用的 NVIDIA 驱动、Miniconda、FFmpeg/FFprobe，确保 `conda`、`ffmpeg`、`ffprobe` 在终端可用。主要在双 V100 上验证，其他GPU组合需自行验证兼容性；当前Whisper识别需要CUDA，不提供CPU识别模式。克隆源码并进入项目目录后执行：

```powershell
powershell -NoProfile -File scripts/install.ps1
.\.venv\python.exe -s scripts/create_icon.py
powershell -NoProfile -File scripts/build.ps1
```

安装会下载依赖、CUDA运行库及约3GB Whisper模型，需要联网、足够的显存和磁盘空间。安装脚本使用锁定依赖；CUDA wheel 从官方PyPI分段下载并核对SHA256；模型从 Systran 官方模型仓库下载。安装器不改驱动、系统页面文件或其他项目环境。运行时使用 `-s` 禁用用户级 Python 包，避免受其他工程影响。

当前实测：Python3.12、CTranslate2 4.8.3、faster-whisper1.2.1、CUDA12.8运行库。本组合不需要安装CUDA Toolkit或最新cuDNN；不要直接把旧Volta卡的库更新到不兼容版本。

## 验证

v0.5.2在本机通过79项自动检查，覆盖多接口调度、RPM/429、恢复、用量计数、GUI及真实GPU导出。v0.5.6通过91项不占用GPU的检查，覆盖审校接口修正、已有任务策略保留、8接口逐个尝试与失败汇总、切换过程记录和最终告警，以及原有固定接口列表、RPM/429、恢复和用量检查。真实任务运行期间保留生产进程，不重复占用GPU跑导出回归。完整测试包含GPU与FFmpeg用例；安装脚本使用的锁定依赖包含pytest和构建工具。

```powershell
.\.venv\python.exe -s -m submaker --diagnose
.\.venv\python.exe -s -m pytest -q
.\.venv\python.exe -s scripts/smoke_gpu.py
.\.venv\python.exe -s scripts/validate_long_asr.py
.\.venv\python.exe -s scripts/validate_integration.py
```

最后两个脚本读取 input 中的测试MP4。综合测试只连接本机模拟API，成品放在 `output/validation`，字幕明确为测试内容，不是正式译文。大型 CUDA 下载 wheel 可在安装成功后删除，模型文件需要保留。

## 提交仓库前

`.gitignore`默认排除本地配置/凭据文件、任务数据库和恢复点、模型权重、输入/输出媒体、字幕、日志、虚拟环境、构建与交付包。`docs`下的运行JSON报告和旧截图默认排除，仅保留第三方许可索引及四张经检查的演示截图。公开源码保留官方服务地址预设和测试占位地址；本地填写的私有接口地址、模型ID和凭据引用只保存在被忽略的`data/`中。

在已初始化的Git仓库中，提交前检查暂存内容：

```powershell
git status --short --ignored
git diff --cached --stat
git ls-files -- data models input output delivery .venv .env
```

最后一条正常应无输出。`.gitignore`只保护未跟踪文件，不会清理已提交的内容，也不能识别粘贴进源码或截图的秘密。已跟踪的私有文件需先从Git索引移除；若Key曾公开，需更换Key并清理相关历史。`delivery/`内已有旧包只用于本地交付，不能因新增忽略规则就视为可公开附件。

项目依赖及模型的许可仍分别适用；本机FFmpeg由既有WinGet安装提供。不要未经许可重新分发影片、用户数据或打包的第三方组件。
